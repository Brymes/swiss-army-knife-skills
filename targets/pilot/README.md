# Pilot target index

The two authorized live targets for the `sak` pilot: DVWA and vuln-bank. Both run
on loopback Docker, or on Legion reached through an SSH local forward. This page
is the single index for pins, ports, credential locations, scope files, run
commands, evidence and cleanup.

The consolidated operator runbook is [`docs/pilot.md`](../../docs/pilot.md); the
four-cell matrix is [`acceptance.md`](acceptance.md). Per-target detail lives in
[`targets/dvwa/README.md`](../dvwa/README.md) and
[`targets/vuln-bank/README.md`](../vuln-bank/README.md).

> Both targets are intentionally vulnerable. Authorized loopback labs and the
> owner-approved Legion path only. Never expose a port beyond loopback, never
> load real data, and never commit a credential.

## DVWA

- Upstream: https://github.com/digininja/DVWA
- Harness: [`targets/dvwa/`](../dvwa/)
- Compose file: `targets/dvwa/compose.yaml`, container `sak-dvwa`
- Ports: `${DVWA_PORT:-8080}` on `127.0.0.1` to container `80`
- Health: a PHP socket check against container port `80`
- Credentials: `targets/dvwa/.env`; `DVWA_USERNAME` and `DVWA_PASSWORD` are read
  by `setup.sh` and by the Playwright scenario through `${DVWA_USERNAME}` and
  `${DVWA_PASSWORD}` substitution
- Scope: `runs/pilot-dvwa-kali/scope.md` or `runs/pilot-dvwa-mac/scope.md`,
  generated by `run.sh`; the allowed host is the single loopback origin
- Scenario: `targets/dvwa/checks.json` (login, low security, SQLi and XSS pages)
- Expected evidence: `scope.md`, `threat-model.md`, `plan.json`, `logs/`,
  `steps/`, `findings/nuclei.json`, `findings/playwright.json`, `findings.json`,
  `evidence/`, `REPORT.md`, `FINDINGS-DETAIL.md`, `NEEDS-VALIDATION.md`
- Cleanup: `docker compose -f targets/dvwa/compose.yaml down -v --remove-orphans`

Start and stop without the harness:

```sh
docker compose -f targets/dvwa/compose.yaml up -d
docker compose -f targets/dvwa/compose.yaml ps
docker compose -f targets/dvwa/compose.yaml down -v
```

`setup.sh` also resets the DVWA database through `/setup.php`, so a failed login
is usually fixed by `down -v`, `up -d`, then `sh targets/dvwa/setup.sh
--url http://127.0.0.1:8080`.

## vuln-bank

- Upstream: https://github.com/Commando-X/vuln-bank
- Harness: [`targets/vuln-bank/`](../vuln-bank/)
- Pin: `41c5b056f9ae8a8b15c77ea79f1419356b321634` on `main`, MIT license
- Checkout: `vendor/external/vuln-bank`, gitignored, never vendored
- Compose file: `docker-compose.yml` inside the external checkout
- Ports: `127.0.0.1:5000` web and API, `127.0.0.1:8080` second mapping,
  upstream-pinned `5432:5432` Postgres on all interfaces
- Health: `GET /healthz` returns HTTP 200 with the database up
- Credentials: seeded lab accounts documented in
  `docs/targets/vuln-bank.md#test-accounts`; no credential is committed and the
  harness never prints one
- Scope: `runs/pilot-vuln-bank-kali/scope.md` generated by `run.sh`; the Mac cell
  writes the same allowlist explicitly in the runbook block. Template:
  `targets/vuln-bank/scope.example.md`
- Scenario: `targets/vuln-bank/playwright/vuln-bank.spec.js` (health and login
  readiness only)
- Expected evidence: `scope.md`, `threat-model.md`, `checks.json`, `plan.json`,
  `logs/`, `steps/`, `findings/nuclei.json`, `findings.json`,
  `playwright-results.json`, `playwright-stderr.log`, `REPORT.md`,
  `FINDINGS-DETAIL.md`, `NEEDS-VALIDATION.md`
- Cleanup: `(cd vendor/external/vuln-bank && docker compose down --volumes)`

Clone and start:

```sh
sh targets/vuln-bank/clone.sh --dry-run
sh targets/vuln-bank/clone.sh
sh targets/vuln-bank/run.sh --dry-run
sh targets/vuln-bank/run.sh --execute --run-dir runs/pilot-vuln-bank-kali
```

The upstream compose pins Postgres to `5432` on every interface. Run the lab on
an isolated host or block `5432` at the host firewall; stop any local Postgres
that already owns the port. The harness never queries it.

## Legion access for both targets

`legion-ts` is the expected SSH alias. The Mac cells use:

```sh
sh scripts/legion-tunnel.sh --check
sh scripts/legion-tunnel.sh --execute 8080
sh scripts/legion-tunnel.sh --execute 5000
```

Each forward is `ssh -N -L 8080:127.0.0.1:8080 legion-ts` (or `5000`). The
target stays loopback as seen by the Mac, so the scope allowlist is unchanged.
Do not run the Mac cell through a Windows-to-WSL forward; run inside Kali
instead. Tailscale, WSL and firewall detail is in
[`docs/targets/legion-tailscale.md`](../../docs/targets/legion-tailscale.md).

## Common rules

- Loopback or the owner-approved Legion path only; no external scanning.
- `sak run --execute` enforces `scope.md` and the request/time budget.
- No brute force, denial of service or destructive writes. vuln-bank writes need
  owner approval and a recorded account pair, object id and expected change.
- Candidate findings stay `needs_validation`; only a verifier promotes one, with
  evidence, through `sak findings status`.
- Browser, Docker, Node and Nuclei installs are operator actions. `sak doctor`
  prints the exact command; nothing is installed by `sak`.
- Run directories under `runs/` are evidence, not source. They stay out of git.
